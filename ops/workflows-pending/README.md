# (보관) MT-001 해소 전에 준비해 두었던 워크플로

**이 폴더는 더 이상 적용 대기 상태가 아닙니다.** 2026-08-27에 토큰에 `workflow`
스코프가 부여되어 여기 있던 두 파일을 `.github/workflows/` 로 적용했고, 지금은
그쪽이 정본입니다. 이 폴더의 사본은 그때의 기록으로만 남겨 둡니다.

**여기 있는 파일을 고치지 마세요.** 워크플로를 바꿔야 하면 `.github/workflows/` 를
직접 고치면 됩니다(이제 push 됩니다).

## 무슨 일이 있었나

GitHub Actions는 `.github/workflows/` 안의 파일만 실행합니다. 그런데 그 경로를
바꾸는 커밋은 토큰에 `workflow` 스코프가 있어야 push 할 수 있는데, 그게 없었습니다
(MT-001). 그래서 `data/*.csv` 는 매일 자동으로 쌓이는데 그 CSV로 `data/brief.json` 을
다시 만드는 단계가 자동으로 돌지 않는 상태가 이어졌습니다.

앱은 `brief.json` 만 읽으므로, 그 파일의 `kr.date` 가 5일 이상 묵으면 실제 휴장이
아닌데도 한국 섹션이 "연휴/휴장" 안내로 덮입니다. **두 차례 실제로 발생했습니다**
— 2026-08-16~20, 2026-08-22~26 (`.forge/state.json` 의 INC-001).

준비된 내용을 로컬 브랜치에만 두면 다른 사람이 볼 수 없고 나중에 cherry-pick 할 때
충돌할 수 있어서, push 가 되는 이 경로에 최종본 그대로 두었습니다. 해소 시 복사
한 번으로 끝나도록 한 것이고, 실제로 그렇게 적용했습니다.

## 적용된 내용

| 항목 | 이전 | 지금 |
|---|---|---|
| make_brief 실행 | 없음 | 있음 — 이게 없어서 brief.json이 안 갱신됐다 (핵심) |
| 브리핑 실패 처리 | 해당 없음 | `continue-on-error` + 마지막에 잡 실패. 수집 결과는 살리되 실패를 조용히 넘기지 않음 |
| 패키지 설치 | `pip install requests pandas` (버전 없음) | `pip install -r requirements.txt` — H-1 |
| 액션 버전 | `@v4`, `@v5` (태그) | 커밋 SHA 고정 — 태그는 옮겨 달릴 수 있다 |
| 체크아웃 토큰 | 기본값(`.git/config`에 저장됨) | `persist-credentials: false`. push는 마지막 스텝에서 명시 전달 |
| 권한 범위 | 워크플로 전역 `contents: write` | 전역 `{}` + 잡 단위 `contents: write` |
| `git pull --rebase` | 커밋 앞 — 워킹트리가 더러워 항상 거부되는 죽은 줄 | 커밋 뒤로 이동 — 실제로 동작 |
| `probe.yml` | origin에 남아 있음 | 삭제됨 |
